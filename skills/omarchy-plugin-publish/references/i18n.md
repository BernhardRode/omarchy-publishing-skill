# Translation readiness (i18n)

**Source basis: additional recommendation.** No marketplace rule, scanner finding or sampled maintainer review requires translation support. Report it separately from policy findings, never as a submission blocker, and never delay a submission the user wants to send now just to finish it.

The goal is narrow: someone who forks the plugin can ask an AI agent to "translate this plugin into Portuguese" and get a working result by adding **one data file**, without touching QML, helpers or the manifest. That only works if every user-visible string already lives in one catalog with stable keys.

## What "prepared" means

- One English source catalog, `i18n/en.json`, a flat JSON object of `"key": "string"`. English is the fallback for every missing key.
- A translation is `i18n/<lang>.json` or `i18n/<lang>_<REGION>.json` (`de.json`, `pt_BR.json`), same keys, translated values. Adding a language needs no code change.
- Every user-visible string in QML goes through one lookup function; no user-visible literal remains inline.
- Placeholders are named (`"Syncing {count} files from {host}"`), never built by concatenating fragments. Word order differs between languages; `tr("a") + name + tr("b")` cannot be translated correctly.
- Plurals use separate keys (`files.one`, `files.other`, plus `few`/`many` where a language needs them), not `n === 1 ? "file" : "files"` in code.
- Dates, times and numbers are formatted with the locale (`Qt.formatDateTime`, `Qt.locale()`, `Number.toLocaleString(Qt.locale())`), not assembled by hand.
- A `TRANSLATING.md` in the plugin root (template: [translating.md](../assets/translating.md)) tells a human or an AI agent exactly what to do. It must be an ordinary document: never `AGENTS.md`, `CLAUDE.md` or anything under `.claude/`, `.agents/` etc. — those are an observed reviewer blocker (see review-patterns.md).

## What must not be translated

Plugin id, manifest keys and values, entry-point paths, settings keys, IPC/command names, file names, environment variable names, log lines or codes that code or users grep for, and anything a helper script parses. If a helper returns text that QML displays, make the helper return a stable code (`"error": "network-timeout"`) and map the code to a catalog key in QML. That keeps a single catalog and keeps helpers locale-independent.

## Pattern for QML plugins

Omarchy/Quickshell does not document installing a Qt `QTranslator` for third-party plugins as of the research date, so don't assume `qsTr()` gets translated at runtime. Check the current [development guide](https://plugins.omarchy.org/develop.html); if it now documents a translation mechanism, prefer it. Otherwise ship a small loader in the plugin itself. Adapt this to the plugin's structure and Quickshell version, and verify with `qmllint` (requirements.md) — it is a sketch, not tested against every Quickshell release:

```qml
// I18n.qml — instantiate once, pass down or expose via a property.
import QtQuick
import Quickshell
import Quickshell.Io

Scope {
    id: root
    // Override for testing or a user setting; defaults to the session locale ("de_DE").
    property string locale: Qt.locale().name
    readonly property string lang: locale.split(/[_-]/)[0]
    readonly property var strings: merge([en.text(), byLang.text(), byLocale.text()])

    function file(name) {
        return Qt.resolvedUrl("i18n/" + name + ".json").toString().replace(/^file:\/\//, "")
    }
    FileView { id: en;       path: root.file("en");        blockLoading: true }
    FileView { id: byLang;   path: root.file(root.lang);   blockLoading: true }
    FileView { id: byLocale; path: root.file(root.locale); blockLoading: true }

    // Later catalogs override earlier ones; malformed or missing files are skipped.
    function merge(texts) {
        const out = {}
        for (const t of texts) {
            if (!t || t.length > 262144) continue
            try {
                const obj = JSON.parse(t)
                for (const k in obj) if (typeof obj[k] === "string") out[k] = obj[k]
            } catch (e) {}
        }
        return out
    }

    function tr(key, args) {
        let s = strings[key] ?? key
        if (args) s = s.replace(/\{(\w+)\}/g, (m, n) => n in args ? String(args[n]) : m)
        return s
    }

    // Extend pluralCategory for languages with more forms (pl, ru, ar, ...).
    function pluralCategory(n) { return n === 1 ? "one" : "other" }
    function trn(key, n, args) {
        const k = key + "." + pluralCategory(n)
        return tr(k in strings ? k : key + ".other", Object.assign({ count: n }, args || {}))
    }
}
```

Usage: `text: i18n.tr("status.connected", { name: device.name })`, `text: i18n.trn("files", count)`. Keep `textFormat: Text.PlainText` on sinks that show catalog strings with interpolated external data — translations come from forks and the interpolated values are still untrusted (review-patterns.md, "Treat external text and images as data"). Keys in `en.json` should be grouped by area (`bar.`, `panel.`, `error.`, `settings.`) and named for meaning, not for their English wording.

Layouts should survive ~40% longer strings (German, Finnish) and right-to-left languages: prefer anchors/`RowLayout` with `elide` over fixed widths, and don't hard-code left/right where `LayoutMirroring` would apply.

## Audit and fix

1. Inventory user-visible strings: QML `text`, `title`, `placeholderText`, tooltips, toasts/notifications, menu labels, dialog buttons, error messages, empty states, and strings helpers print that the UI shows. Include README-documented in-panel commands only where they are displayed text, not command names.
2. Report translation readiness in its own section of the readiness report: catalog present or not, number of inline literals remaining, concatenated or hand-pluralized strings, helpers returning prose instead of codes.
3. When the user authorized fixes, externalize strings into `i18n/en.json` with the loader, add `TRANSLATING.md`, and keep behavior identical in English. Don't add machine translations unless the user asks; an unreviewed translation shipped in the submission is extra review surface.
4. Verify: `qmllint`; `jq -e 'type=="object" and all(.[]; type=="string")' i18n/*.json`; every key used in QML exists in `en.json`; every translation's keys are a subset of `en.json`; and, where a runtime is authorized, launch with `LANG=de_DE.UTF-8` and a test catalog to see the fallback work.
5. Do this before assembling the review snapshot. Any change after validation needs fresh evidence (SKILL.md, "Assemble the review snapshot").

`scripts/readiness-check.sh` reports inline QML literals and catalog key drift as notes, never as blockers.
